## Chức năng

- Tài khoản nền tảng: catalog thêm/đổi tên/tắt/sắp xếp; tìm theo tên/login, lọc và phân trang. Tạo metadata + mật khẩu đầu + nhiều người xem trong một transaction. Picker có tên/mã/chuyên môn, giữ tick khi tìm. Staff chỉ xem/copy/cập nhật tài khoản được chia sẻ, không sửa metadata hoặc chia sẻ tiếp.
- Mật khẩu nền tảng: mã hóa AES-GCM với khóa ngoài source/DB; giữ nguyên khoảng trắng được chấp nhận, không áp min11 của website. So sánh chính xác, cùng mật khẩu không tạo phiên bản. Khóa row + expected_version + idempotency chống cập nhật lặp. Conflict 409 có nút lấy phiên bản mới và giữ input. Reveal kiểm quyền mỗi lần, no-store và **không lưu plaintext vào idempotency**. Secret trong UI xóa khi đóng/chuyển trang/blur hoặc sau 30 giây; sao chép luôn yêu cầu server kiểm quyền lại. HTTP trình duyệt không có Clipboard API sẽ hiện hướng dẫn sao chép thủ công.
- Lịch sử mật khẩu: Admin-only; lọc nền tảng/tài khoản/người cập nhật/ngày Việt Nam, phân trang. Metadata không chứa secret; trước/sau phải reveal riêng. Previous/current FK buộc cùng account; lịch sử bất biến. Metadata legacy đánh dấu được ghi nhận lúc nâng cấp vì trước đây chưa có snapshot metadata.
- Nhật ký sử dụng chung: ngừng insert, `/audit` trả 410 cho Admin. Audit cũ giữ nguyên. Giữ task_events, submissions/reviews, report revisions, employment/request history và credential versions. Quyết định thiết lập, lý do đổi mẫu và thu hồi grant được lưu trong dữ liệu nghiệp vụ tương ứng. Log API chỉ lỗi vận hành đã lọc, không access logging/body/cookie/secret.
- Nhân sự: không còn form ứng viên/phỏng vấn/tuyển dụng. Danh sách đang làm/đã nghỉ, mã giữ số0 đầu, nhiều vị trí, phase khác employment type; drawer ba tab; chọn ảnh từ tài liệu riêng với preview kiểm ACL; CCCD/thuế/BHXH/ngân hàng/lương mã hóa qua endpoint nhạy cảm có quyền riêng; xuất XLSX theo filter/scope, không xuất trường nhạy cảm. Vị trí hồ sơ không tự cấp/revoke grants. Hồ sơ cũ chưa có mã/ngày vào làm giữ null, HR bổ sung, không chế mã mới.
- Nghỉ việc: quy trình hiệu lực ngay chỉ chạy khi Admin xác nhận policy; yêu cầu ngày/lý do/xác nhận bàn giao. Archive, khóa user/session, revoke grants/account sharing trong transaction; giữ task/report/password history. Liệt kê task bàn giao, không tự giao người khác hoặc tự đổi mật khẩu bên ngoài. Endpoint LEFT cũ được retire để không bỏ qua policy. Chưa hỗ trợ đặt lịch tương lai.
- Đội ngũ: wizard tạo user + nhiều JOB + ACCESS + liên kết nhân viên hiện hữu atomically. Admin chỉ ALL, JOB chỉ SELF; manager/reviewer picker theo scope và server kiểm lại. Thêm quyền không xóa quyền cũ, có permission_version và chống trùng khoảng quyền. Bootstrap/min11/Argon2/startup giữ nguyên.
- Thiết lập: nền tảng, tình trạng khóa an toàn, lịch làm việc, policy thông báo/bàn giao, checklist theo loại hình bằng checkbox. Không nhập JSON/UUID/khóa trong UI. Sinh nhật 5 ngày làm việc có policy, holiday, retry dedupe, năm mới và bỏ ngày 29/2 không hợp lệ; không tự bật nhắc hết thử việc/hợp đồng.

## Migration 006 và cập nhật Windows

Dừng API/worker và sao lưu DB + DATA_DIR trước khi cập nhật. Giữ nguyên `.env` và VAULT_KEY; key sao lưu riêng có kiểm soát. Không chạy seed/bootstrap/reset để nâng cấp.

```powershell
cd D:\AI\task
node .\scripts\backup.mjs D:\SuperNetBackups
git pull --ff-only
npm ci
npm run upgrade:preview
npm run build
npm run migrate
npm start
```

Cửa sổ thứ hai: `npm run worker`. Mở `http://localhost:3002`, Ctrl+F5; máy khác dùng IP LAN máy chủ cổng3002 theo [WINDOWS.md](WINDOWS.md). Server vẫn mặc định `0.0.0.0:3002`.

`upgrade:preview` chỉ đọc: platform cũ/nhãn gần trùng, hồ sơ nhân viên cũ và user link bị trùng. Nếu có trùng, HR/Admin phải xác nhận mapping và sửa dữ liệu cụ thể trước migration; không tự merge/unlink/xóa. Employee code/joined_on legacy không backfill theo suy đoán. Platform giữ spelling cũ, không đổi các account/grants sang mô hình chia sẻ khác.

006 bổ sung platform catalog, current/previous credential pointer và revision/snapshot, employee fields/positions/documents, FK asset employee, business settings/grant history và authorization fingerprint của idempotency. Backfill credential metadata tạm tắt đúng UPDATE guard trong transaction rồi bật lại; ciphertext/actor/ID/thời gian không đổi. FK buộc previous/current cùng account. Không drop audit cũ.

Các phản hồi reveal legacy từng được cơ chế idempotency cũ lưu trong `response.secret` được loại bỏ khỏi cache vận hành; mật khẩu gốc trong credential_versions vẫn giữ nguyên ciphertext. Cache cũ thiếu authorization fingerprint không được replay, cần tải lại giao diện và gửi yêu cầu mới. Cache mới không bypass quyền vừa hết hạn/thu hồi. Những bản backup cũ có thể chứa response reveal legacy; giữ backup private theo kế hoạch hiện có.

Nếu dùng runtime role riêng, cấp DML/sequence cho các bảng mới theo [SCHEMA.md](SCHEMA.md). Migration role cần sở hữu bảng/trigger hiện có. Migration lỗi rollback transaction; không start code mới với schema cũ. Rollback bằng restore vào DB/files riêng và code/key tương ứng, không dùng down migration xóa lịch sử.
